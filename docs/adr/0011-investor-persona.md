# ADR-0011: PE投資家向け報告ペルソナをメトリクス定義テーブル方式で追加する

## ステータス

採用

## コンテキスト

- 既存のレポートペルソナはプロジェクト関係者向けであり、PE投資家がポートフォリオ会社のKPIを横断的に確認する用途を明示していない。
- `docs/research/2026-07-09-deep-research.md` は、ILPA Portfolio Company Metrics Templateの2019年版が公開され、2027年1月に改訂版が予定されていることを確認している。
- 既存設計には `personaResolver`、`reportPermissionFilter`、`profileReports` があり、ペルソナ別の表示と権限制御を拡張できる。
- 予定仕様ID: PrjOps `REQ-039` / `SPEC-INT-066` / `AC-039-1`。実装コード参照を追加しない本ADR段階では、`REQ`/`SPEC-INT` のspec-id登録は実装フェーズへ送る。

## 決定

- `investor` ペルソナを新設する。
- 初期フィールドセットはILPA Portfolio Company Metrics Templateの2019年版を暫定ベースラインとする。
- フィールドセットはコードにハードコードせず、メトリクス定義テーブルで管理する。定義にはID、表示名、単位、集計粒度、計算式または入力元、必須/任意、版、適用開始日を持たせる。
- 2027年1月のILPA改訂版は、メトリクス定義の版追加として吸収する。既存レポートの過去版再現性を壊さない。
- 権限は既存の `personaResolver` / `reportPermissionFilter` / `profileReports` の延長で実装し、投資家が閲覧できる会社・プロジェクト・メトリクス範囲を明示的に制御する。

## 根拠

- ILPAテンプレートはPE投資家向けの既存標準として使いやすいが、改訂予定が明確にある。フィールドをコード固定すると改訂吸収時に差分が大きくなる。
- メトリクス定義テーブル方式なら、導入企業ごとの非公開KPIや任意項目もコード変更なしで追加できる。
- 既存ペルソナ/権限フィルタの拡張に留める方が、別系統のレポート基盤を作るより実装面積が小さい。

## 影響

- メトリクス定義テーブルと、版管理された定義データの投入手順が必要になる。
- investorペルソナは、プロジェクト運営者向けの詳細コメントや内部リスクメモをそのまま見せない。表示可否は権限フィルタで管理する。
- ILPA 2027年版公開時に定義データを追加し、差分レビューを行う。
