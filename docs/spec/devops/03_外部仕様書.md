# 文書3: 外部仕様書 AIエージェント主導DevOps運用基盤

- 文書ID: DOC-EXT-03
- 版: 1.0（2026-07-03）
- 対象読者: 後続実装モデル、社内ユーザー（PRF-M/PRF-L/PRF-G）、関連企業窓口
- 上位文書: DOC-PRD-02。各項目は対応するREQ-IDを明記する。
- 記載範囲: **ユーザーおよび関連企業から見える振る舞い・インターフェースのみ**を記載する。内部実装（パイプライン内部構成、シークレット管理、データベース設計等）は内部仕様書DOC-INT-04に記載し、本書には含めない。

## 1. 利用者区分と接点

| 利用者 | 接点 |
|---|---|
| PRF-M（メンバー） | GitHub（PRコメント）、Teams（通知）、Outlook（日次レポート） |
| PRF-L（リーダー） | Teams（承認カード・通知）、Outlook（日次・週次レポート）、GitHub |
| PRF-G（マネージャー） | Teams（エスカレーション・承認カード）、Outlook（週次・月次レポート、棚卸し） |
| 関連企業（国内外数十社） | Teams（ゲスト参加チャネルの通知）、メール通知。GitHubアクセスは付与された権限範囲のみ |

## 2. 通知・PRコメント仕様（社内向け）

**SPEC-EXT-001 ビルド失敗PRコメント**（REQ-001, REQ-002）
書式（Markdown、以下の4節を必ずこの順で含む）:
1. `## ビルド失敗の一次調査結果`（見出し固定）
2. `原因分類:` の後に5分類のいずれか1つ（テスト失敗／コンパイルエラー／依存関係／インフラ・タイムアウト／不明）
3. `該当箇所:` 失敗ジョブ名、ステップ名、ログ抜粋（最大20行）
4. `修正案:` diffコードブロック（REQ-002対象分類のみ。対象外の場合は「修正案の自動生成対象外です」と明記）
末尾に監査ログ参照ID（`trace_id: <UUID>`）を記載する。

**SPEC-EXT-002 ビルド失敗Teams通知**（REQ-001）
宛先: 該当PRの作成者への個人チャット。内容: リポジトリ名、PR番号、原因分類、PRコメントへのリンク。送信タイミング: SPEC-EXT-001のコメント投稿と同時。

**SPEC-EXT-003 ステージング昇格通知**（REQ-003）
宛先: プロジェクトのTeamsチャネル。内容: 「ステージングへ自動デプロイしました」、コミットSHA（先頭7桁）、TH-001充足の根拠3項目（CI結果／カバレッジ実測値／静的解析結果）を数値付きで表示。

## 3. 承認インターフェース（Teamsアダプティブカード）

**SPEC-EXT-010 本番デプロイ承認カード**（REQ-010, REQ-011）
- 表示項目（順序固定）: (1) プロジェクト名・対象環境「本番」、(2) 変更差分要約（最大10行）、(3) テスト結果サマリ（成功/失敗件数、カバレッジ%）、(4) リスクスコア（0〜100。70以上は赤色「高リスク」バッジ）、(5) ロールバック手順の要約、(6) 承認期限（要求時刻＋30分をJSTで表示）。
- 操作ボタン: 「承認」「却下」「保留（コメント必須）」の3つ。
- 権限挙動: リーダー以上のみ操作可能。メンバーが操作した場合「この操作にはリーダー以上の権限が必要です」とエラー表示し、操作は記録されるが効力を持たない（AC-010c）。
- 時限挙動（TH-002）: 30分無応答でマネージャーへ同一カードを再送。60分で「期限切れ・デプロイ中止」に状態遷移し、カードは操作不能になる。

**SPEC-EXT-011 権限承認カード**（REQ-018）
表示項目: 申請者、対象（リポジトリ/環境）、権限レベル、申請理由、有効期限（TH-007の上限を超える申請は受理段階で拒否済みであること）。ボタン: 「承認」「却下」。承認者ルール: 開発・ステージング＝リーダー、本番・外部企業＝マネージャー。

**SPEC-EXT-012 Sev1宣言カード**（REQ-015）
AGT-INCがSev1候補と判定した場合のみ送付。表示: 影響推定、根拠メトリクス、候補判定時刻。ボタン: 「Sev1として宣言」「Sev2に降格」「誤検知」。宣言操作はリーダー以上のみ有効。

## 4. インシデント関連の見え方

**SPEC-EXT-015 インシデントIssue**（REQ-015）
GitHub Issueとして起票。タイトル書式: `[SevN][プロジェクトID] 事象概要`。本文に、検知時刻（JST）、重大度と分類根拠、影響プロジェクト推定、初動で確認すべき項目チェックリスト、trace_idを含む。ラベル: `incident`, `sev1`〜`sev4`, `auto-triaged`。

**SPEC-EXT-016 エスカレーション通知**（REQ-016）
TH-005の時限で、リーダー→マネージャーの順に個人チャット通知。文面に「未応答のためエスカレーションしました」、経過時間、元Issueリンクを含む。Ackは通知内の「対応します」ボタンで行う。

**SPEC-EXT-017 誤検知候補の確認依頼**（REQ-017）
当番メンバーへ「自動クローズ候補」通知。ボタン: 「クローズ承認」「対応が必要」。24時間無応答の場合はオープン維持（自動クローズしない）。

## 5. プロファイル別定期レポート（HTML/Outlook配信）

共通仕様 **SPEC-EXT-020**（REQ-020）: 件名書式 `[DevOpsレポート][種別] YYYY-MM-DD`。本文HTMLはインラインCSSのみ使用（外部CSS・JavaScript不可）、幅640px基準の単一カラム。ヘッダーに集計期間・生成時刻（JST）・宛先プロファイル名を表示。フッターに配信停止・宛先変更の問い合わせ先を表示。

差分仕様（レイアウトはいずれもヘッダー＋セクション構成。セクションの内容と順序を以下に固定する）:

**SPEC-EXT-021 PRF-M日次レポート**（REQ-021）
セクション順: (1) 本日のあなたのオープンPRとCI状態（表: PR番号/タイトル/CI状態/最終更新）、(2) あなた宛レビュー依頼、(3) あなたが当番の未対応アラート。データは本人分のみ。0件のセクションは「本日はありません」と表示（セクション自体は省略しない）。

**SPEC-EXT-022 PRF-L日次レポート**（REQ-022）
セクション順: (1) プロジェクトCIサマリ（成功率%、失敗ワークフロー一覧）、(2) 直近24時間のデプロイ実績（環境別）、(3) オープンインシデント（Sev別件数と一覧）、(4) あなたの承認待ち（デプロイ・権限）、(5) 滞留状況（レビュー待ち48時間超のPR件数などタスク種別別。メンバー個人名別の集計は表示しない）。

**SPEC-EXT-023 PRF-L週次レポート**（REQ-022）
日次の集計を7日間に拡張し、加えて週次トレンド（CI成功率の前週比、デプロイ回数の前週比）を表示。

**SPEC-EXT-024 PRF-G週次レポート**（REQ-023）
セクション順: (1) 全50プロジェクト横断のDORA指標4種（デプロイ頻度/変更リードタイム/変更失敗率/MTTR。それぞれ今週値と前週比）、(2) Sev1/Sev2一覧、(3) 要注意プロジェクトTop5（選定基準は「変更失敗率降順、同率の場合オープンSev2件数降順」で固定）、(4) 承認滞留（期限切れになった承認要求件数）。

**SPEC-EXT-025 PRF-G月次レポート**（REQ-023, REQ-019）
週次の内容の月間版に加え、権限棚卸しサマリ（総権限数、当月失効数、外部企業アカウント数）を含む。

**SPEC-EXT-026 閲覧権限**（REQ-021〜024）
レポートは宛先本人のプロファイル・担当範囲のデータのみを含む。担当外データの混入はバグとして扱う。配信名簿はAGT-SEC管理の名簿を唯一のソースとする（REQ-024）。

## 6. 関連企業（外部）向けインターフェース

**SPEC-EXT-030 障害通知**（REQ-015, REQ-027）
影響を受ける関連企業のTeamsゲストチャネルおよび登録メールアドレスへ、Sev1/Sev2確定時に送信。内容: 事象概要、影響範囲、現在の対応状況、次回更新予定時刻（Sev1は60分ごと、Sev2は3時間ごとに更新を送る）。言語は企業ごとの設定（ja/en）に従う。内部ログ・スタックトレース・社内Issue本文は含めない。

**SPEC-EXT-031 障害受付**（REQ-015）
関連企業はTeamsゲストチャネルの定型メッセージまたは指定メールアドレスへ障害連絡を送る。AGT-INCは受信から5分以内（TH-004）に受付確認（受付ID付き）を同一チャネル/メールへ自動返信する。

**SPEC-EXT-032 アクセス権の見え方**（REQ-018）
関連企業アカウントには付与されたリポジトリ・権限レベルのみが見える。有効期限の7日前に更新案内（再承認が必要である旨）を自動送信し、期限到来で自動失効する（TH-007）。

**SPEC-EXT-033 リリース事前通知**（REQ-010, REQ-027）
関連企業に影響する本番リリースは、承認完了時点で対象企業へ予定通知（予定時刻、影響、問い合わせ先）を送信する。

## 7. 異常系の見え方（ユーザー視点）

| ID | 状況 | ユーザーから見える振る舞い |
|---|---|---|
| SPEC-EXT-040 | デプロイ失敗（REQ-012） | ロールバック実行通知＋Sev2 Issueリンクがプロジェクトチャネルへ2分以内に届く |
| SPEC-EXT-041 | 承認期限切れ（TH-002） | 要求者とリーダーへ「期限切れによりデプロイを中止しました。再申請してください」通知 |
| SPEC-EXT-042 | エージェント停止（REQ-029） | 全プロジェクトチャネルへ「自動運用を一時停止中。手動運用手順に切り替えてください」通知＋手動手順書リンク |
| SPEC-EXT-043 | 権限エラー | 操作者に権限不足の理由と正しい申請経路（SPEC-EXT-011）を提示 |
| SPEC-EXT-044 | 誤検知（TH-006） | SPEC-EXT-017の確認フローに従う。人間確認なしで消えることはない |
