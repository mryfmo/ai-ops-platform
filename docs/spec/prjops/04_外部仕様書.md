# DOC-04 外部仕様書: PrjOps AI基盤（利用者・関連企業から見た振る舞い）

- 版: 1.0 / 作成日: 2026-07-03 / 依存: DOC-03
- 本書は利用者（PRF-01〜05）および関連企業から見える振る舞い・インターフェースのみを定義する。内部実装（データ構造・API・処理ロジック）は一切含めない（内部はDOC-05）。各項は根拠となるPRD要件IDを `[REQ-xxx]` で参照する。

| ID | チャネル | 対象 | 用途 |
|---|---|---|---|

## 2. 報告のしかた（報告者向け仕様）

**SPEC-EXT-010 報告依頼メッセージ** [REQ-003]
毎週水曜09:00 JSTに届く依頼には次が含まれる: プロジェクト名とID、対象期間（月曜〜日曜の日付）、報告方法3種の説明、報告期限（金曜18:00 JST）、前回報告の要約3行。件名形式: `【進捗報告依頼】{プロジェクト名} ({PJ-nnn}) {YYYY-MM-DD}週`（en: `[Status Request] ...`）。

**SPEC-EXT-011 自由文報告** [REQ-005]
依頼メールへの返信またはTeams投稿で、次の6項目を自由文で書けばよい: ①進捗率（0〜100の整数%）②自己申告ステータス（順調/注意/危険 または Green/Yellow/Red）③今週の実績 ④来週の予定 ⑤課題（なければ「なし」）⑥リスク（なければ「なし」）。順不同・見出しなしでも受理される。

**SPEC-EXT-012 聞き返し** [REQ-005 AC-005-1,2]
不足項目がある場合、受信から15分以内に同一チャネルへ「不足: ②ステータス, ⑥リスク」の形式で聞き返しが届く。3回で揃わない場合、報告は「不完全」として登録され、以後の対応は運用担当から人手で連絡される。

**SPEC-EXT-013 受理通知** [REQ-004]
報告が正本に反映されると、報告者へ「受理: {PJ-nnn} {対象週} / 進捗率{n}% / 判定は月曜のレポートで通知」の確認メッセージが届く。この通知が届かない場合は報告未反映を意味する。

**SPEC-EXT-014 Teamsコマンド** [REQ-009, REQ-008]
本システム宛のTeamsメッセージで次の定型コマンドを受け付ける（PRF-02以上）:
- `/action add PJ-nnn "{内容}" @担当者 期限:YYYY-MM-DD` — アクション登録
- `/action done ACT-nnn` — アクション完了
- `/issue close ISSUE-nnn 理由:"{...}"` — 課題クローズ（PRF-02のみ）
- `/status override PJ-nnn {Green|Yellow|Red} 理由:"{...}"` — 機械判定の上書き（PRF-02のみ、理由必須）[REQ-021]
コマンド不正時は正しい書式例を返す。曖昧な自然文でも意図が上記に一致すれば実行前に確認カード（Yes/No）が出る。

## 3. レポート仕様（受信者向け）

**SPEC-EXT-020 共通仕様** [REQ-010, 016]
- 形式: 自己完結HTML 1ファイル添付（2MB以下）。件名: `【{種別}レポート】{対象範囲} {対象期間}`。
- 言語は受信者登録の優先言語（ja/en）。数値・色は言語間で完全一致 [REQ-016]。
- 全レポート共通ヘッダー: システム名／レポートID（RPT-...）／対象期間／生成日時／データ取得時点。フッター: 問い合わせ先、機密表示（PRF-05向けは「Confidential — for investor use only」）。
- 色の視覚仕様: Green=#2e7d32、Yellow=#f9a825、Red=#c62828。色だけに依存せず必ず文字ラベル併記（色覚対応）。

**SPEC-EXT-021 プロファイル別レイアウト**（正本はDOC-03 §4.5の表。ここでは画面構成のみ規定）[REQ-011〜015]
- PRF-01: セクション1「あなたのアクション」（期限昇順テーブル: ID/内容/期限/状態。期限超過行は赤帯）、セクション2「所属プロジェクトの状態」（PJ名と色ラベルのみ）。
- PRF-02: セクション1「プロジェクトサマリ」（PJごとに: 色、機械判定と自己申告の併記 [REQ-007 AC-007-2]、進捗率と計画線、未報告表示 [REQ-006 AC-006-2]）、セクション2「課題・アクション詳細」。
- PRF-03: セクション1「色分布ヒートマップ」（PJ×週の色マトリクス、直近8週）、セクション2「Red/Yellow プロジェクト一覧」（Red→Yellow順、各3行要約）、セクション3「横断課題・エスカレーション履歴」。前週差分（色が変化したPJ）を先頭に明示。
- PRF-04: A4縦1ページ相当。冒頭「結論」3行→色分布ドーナツグラフ（インラインSVG）→重要トピック上位5件（各2行）→前月差分。個人名なし。
- PRF-05: 表紙（期間・機密表示）→ポートフォリオサマリ→出資対象PJ別1ページ（マイルストーン達成状況、色、次四半期の見通し）。社内課題詳細・個人名・社内固有情報（部門名・社内システム名）は含まれない [REQ-015]。

**SPEC-EXT-022 配信スケジュール（受信者から見た約束）** [REQ-011〜015, 018]
- PRF-01/02/03週次: 毎週月曜08:00〜10:00 JSTの間に受信。
- PRF-03月次: 毎月第1営業日08:00〜10:00 JSTの間に受信（承認不要）。
- PRF-04月次: 承認完了後1時間以内に受信。
- PRF-05四半期: 承認完了後1時間以内に受信。
- 障害時は遅延通知メールが同経路で届く（レポートが黙って欠落することはない）[REQ-031]。

**SPEC-EXT-023 未達・エラー時の見え方** [REQ-019]
検証NGで配信保留になった場合、受信者には何も届かず、運用担当のみに通知される。受信者向けの再送は同一レポートIDで行われ、件名末尾に `(再送)` が付く。重複して2通届くことはない [REQ-018 AC-018-2]。

## 4. 承認者（PRF-03）向け仕様

**SPEC-EXT-024 承認フロー** [REQ-017]
1. 生成完了後、承認者へTeamsカードとメールが届く。内容: レポートID、対象（PRF-04月次/PRF-05四半期）、プレビュー（HTML添付）、ボタン「承認」「差し戻し」。
2. 「承認」押下で即配信キューへ。 「差し戻し」はコメント入力必須で、AGT-04が再生成→再度承認依頼（回数無制限）。
3. 24時間無応答: 代理承認者（マスタで事前指名）へ同一カードが届く。さらに24時間無応答: 配信は保留のまま、対象受信者へ遅延通知、承認者・代理・運用担当へ督促。
4. 全操作は操作者・日時・コメント付きで記録される旨がカードに明記される [REQ-021]。

## 6. 関連企業（外部組織）から見た振る舞い

- SPEC-EXT-026: 関連企業の担当者は、自社が参加するプロジェクトの依頼・リマインド・受理通知・（登録があれば）PRF-01/02レポートのみを受信する。他社の情報は一切届かない [REQ-011〜013 閲覧権限]。
- SPEC-EXT-027: 海外企業向けメッセージは英語（既定、ASM-002）で、日時は「2026-07-06 08:00 JST (UTC+9)」形式でJSTとUTCオフセットを併記する。
- SPEC-EXT-028: 本システムから関連企業へ届くのは定型メッセージ（依頼・リマインド・受理・レポート）のみ。交渉・非定型連絡は従来どおり担当PMの名義・手動で行われる（DOC-02 §4）。
