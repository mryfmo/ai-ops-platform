# DOC-02 将来プロセス設計（TO-BE）: AIエージェント主導のPrjOps業務プロセス

- 版: 1.0 / 作成日: 2026-07-03 / 依存: DOC-00, DOC-01

## 1. 設計方針

1. **正本の一元化**: 分散したExcel・メール・手元資料を廃し、GitHubリポジトリ `prjops-data` を唯一の正本とする（ASM-005）。
2. **エージェント主導・人間承認**: 収集・集計・生成・配信・追跡はAIエージェント（AGT-01〜07）が実行し、人間は判断と承認のみを行う。エージェントの開発・保守はClaude Code（PRE-01）で行い、実行時はClaude Agent SDK経由でClaude APIを呼ぶ（ASM-006）。
3. **判定基準の機械化**: ステータス色・エスカレーション条件を数値基準に置き換え、主観のばらつき（ISS-009）を排除する。
4. **時差非依存**: 収集を非同期化（Teams/メールでいつでも報告→エージェントが随時取り込み）し、海外企業の時差遅延（ISS-005）を吸収する。

## 3. AS-IS→TO-BE 置換対応表（どの人手プロセスを・なぜ・どのエージェントに置き換えるか）

| AS-IS | 置換先 | 置換理由 | 人間に残る部分 |
|---|---|---|---|
| PROC-01 依頼・督促 | AGT-05＋AGT-06（TOBE-01, 03） | 定型・高頻度・判断不要のため完全自動化が可能（ISS-001対策） | なし |
| PROC-02 受領・転記 | AGT-02（TOBE-02） | 転記ミス（ISS-002）の根絶。自由文からの構造化はLLMの得意領域 | 解析不能な報告への内容確認（AGT-02が本人へ自動で聞き返し、3回失敗で人間へ） |
| PROC-03 集計・整形 | AGT-03＋AGT-04（TOBE-04, 05） | 数値基準による機械判定でISS-009を解消 | なし |
| PROC-04 課題・リスク台帳更新 | AGT-02＋AGT-06 | 台帳を正本リポジトリ内の構造化データに統合（ISS-007対策） | 課題のクローズ判断はPRF-02が実施 |
| PROC-05 階層別資料の再編集 | AGT-04（TOBE-05） | プロファイル別テンプレート（PRE-04）で粒度を仕様として固定（ISS-003対策） | なし |
| PROC-06 会議運営・議事録 | **スコープ外**（本システムでは扱わない） | 会議自体の運営は対象業務から除外。議事録内のアクションのみPRF-02がTeamsコマンドで登録 | 会議運営全般 |
| PROC-07 アクションフォロー | AGT-06（TOBE-10） | 期限は構造化データで機械監視可能（ISS-004対策） | エスカレーション受領後の裁定（PRF-03） |
| PROC-08 関連企業との連絡調整 | AGT-02＋AGT-05が定型部分を代替 | 報告収集・リマインドの定型連絡は自動化（ISS-005対策）。言語はASM-002に従い日英対応 | 交渉・非定型調整はPM（PRF-02）が継続 |
| PROC-09 経営・投資元報告 | AGT-04＋承認ゲート（TOBE-07〜09） | 週次データからの自動生成で鮮度向上（ISS-008対策）。対外報告のため人間承認を必須化（ASM-004） | PRF-03による承認（DP-3を承認ゲートとして形式化） |
| PROC-10 テンプレート維持 | GitHubリポジトリでのバージョン管理に置換 | 旧版利用（ISS-010）をPull Request運用で防止 | テンプレート変更の承認（PRF-03） |

## 4. 人間とAIの権限分担（正本。DOC-03/04/05はこの表に従う）

| 処理 | AI（エージェント） | 人間 |
|---|---|---|
| データ収集・正規化・正本更新 | 実行（AGT-02） | 関与しない |
| ステータス判定・リスクスコア | 算出（AGT-03） | PRF-02は判定に異議があれば上書き可（上書きは監査ログに記録） |
| PRF-01〜03向けレポート | 生成・検証・配信まで自動 | 関与しない（受領のみ） |
| PRF-04/05向けレポート | 生成・検証まで自動 | **配信はPRF-03の承認必須**（ASM-004）。承認期限24時間、超過でPRF-03の代理承認者へエスカレーション、さらに24時間で配信保留のままPRF-04へ遅延通知 |
| 課題・アクションの登録 | 報告文からの自動起票（AGT-02） | 起票内容の修正・クローズはPRF-02 |
| 督促・リマインド | 実行（AGT-06）。同一案件への督促は最大3回まで | 4回目以降の対応はPRF-03へエスカレーション |
| 外部（関連企業・投資元）への送信 | 定型レポート・依頼・リマインドのみ可 | 非定型の対外メッセージはAIによる送信禁止（ドラフト作成まで） |
| 正本データの削除 | 禁止（論理削除のみ、AGT不可） | PRF-03のみが削除操作可 |

## 5. 例外・障害時のふるまい（TO-BEの原則）

- エージェント処理が失敗した場合、AGT-01が同一ジョブを最大2回リトライ（間隔10分）し、3回目失敗でPMO運用担当（PRF-03が指名する1名）へTeams通知する。
- AGT-07の検証がNGのレポートは配信されない。NG理由と対象レポートIDが運用担当へ通知される。
- 配信基盤（Graph API等）が停止した場合、レポートは正本リポジトリに保存済みのため、復旧後にAGT-05が未配信分を再送する（重複配信防止はSPEC-INT-052）。
