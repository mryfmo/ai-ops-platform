# LLM・外部入力 Threat Model

## 1. Scope and method

対象は、LLM を呼ぶ8経路（AGT-02、AGT-03、AGT-04、AGT-BLD、AGT-INC、AGT-CHG、page-agent、
teamsConversationAgent）と、主要な外部入力面（Teams、GitHub webhook、XLSX、report ingest）である。

カテゴリ名は [OWASP Top 10 for LLM Applications 2025](https://genai.owasp.org/llm-top-10/)
（参照日: 2026-07-13）だけを正本とした。対策評価はリポジトリ内の実装を直接確認した結果であり、
プロンプト内の注意文だけ、または secret の形式置換だけを prompt injection の完全対策とは扱わない。

- **M**: 実装済み対策がある
- **P**: 部分対策のみ
- **U**: 対策なし
- **N/A**: この経路に該当機能がない

## 5. Uncovered cells and future considerations

以下は未実装であり、現状の対策としては数えない。

1. **Prompt injection**: 8経路すべてに、命令/データ境界の機械的検査や adversarial prompt regression suite はない。
   共通`AnthropicStructuredClient`はwhole-user文字列から既知secretを除去するが、これは一般PII/DLPやprompt injection検出ではない。
2. **Output validation**: AGT-02/03、BLD、INC、CHGの`parse`は型castでありruntime schema検証ではない。
   AGT-03は数値を含む理由文を拒否せず、AGT-CHGは要約をサニタイズせずcardへ渡す。
   page-agentはtool inputだけをZod検証し、`streamText`のfree textはruntime出力検証・サニタイズなしでUIへ返す。
3. **Sensitive data**: `secretSanitizer`は既知形式のredactionで、一般PII・機密分類・DLPではない。
4. **Provenance/poisoning**: INCのmetrics/類似事例、CHGのdiff、AGT-04のrisk summaryにsource署名や
   provenance metadataの検証はない。
5. **Consumption**: Teams/Graph/GitHub webhook/XLSX/ingestにrequest body上限やroute rate limitがない。
   AGT-BLDのAgent SDK queryには明示的なturn/cost上限がない。page-agentは日次cost、5-step、thinking budgetを持つが、
   実出力を直接制限するhard `maxOutputTokens`は設定していない。
6. **System prompt leakage**: system promptへsecretを置かない構成だが、抽出試行の検出・監査はない。
7. **Vector/embedding**: 現在は該当機能なし。将来RAG/vector storeを導入する場合はtenant分離、metadata権限、
   source provenance、embedding ingestion validationを設計gateに追加する。
