# AGMSG-TASK v1 — P005-T09

## Objective

独自client-credentials token cacheを、Microsoftがproductionで推奨するMSAL Node wrapperへ置換し、single-flight/cache/refresh/失敗回復をSDKへ委譲する。

## Work

- 現行公式Microsoft identity/MSAL Node docsと最新compatible packageを確認し、pnpm workspaceへ最小依存 `@azure/msal-node` を追加。
- `ConfidentialClientApplication.acquireTokenByClientCredential` を `https://graph.microsoft.com/.default` 固定で呼ぶinjectable wrapperへ置換。
- ProductionはMSAL client、testは注入fake。空token、null result、不正expiryをfail closed。secret/token/response bodyを例外・ログへ含めない。
- 既存の手製cache/single-flight不足を削除し、MSALのcacheを二重実装しない。
- 同時呼出し、cached result、expiry前更新はwrapper contract/SDK呼出し回数で検証できる最小範囲に限定。失敗後次回呼出しが回復すること。
- config/index/CLIの全token provider callerを移行。scopeやauthorityを任意入力にしない。

## Acceptance

- [ ] official `.default` scope固定。
- [ ] concurrent callsでwrapperが不要な重複 acquisitionを発生させない（必要ならwrapper single-flightは最小実装）。
- [ ] failure promiseを保持せず次回回復。
- [ ] null/empty token拒否、secret/token非露出。
- [ ] networkless tests、dependency audit、full CI green。

## Scope/STOP

Graph auth providerとdirect callers/tests/docs/package lockのみ。tenant token取得禁止。依存解決不能なら証拠付きBLOCKEDで止め、独自OAuth拡張へ逸脱しない。

## Result

Five artifacts + AGMSG-RESULT v1.
