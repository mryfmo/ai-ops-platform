- Added pure `graphNotificationDedupeKey()`: notification `id` is preferred; otherwise a key is returned only for a complete subscription/resource/changeType/etag tuple; optional identity absence returns `null`.

- Audit details and persisted keys do not contain clientState, validation tokens, secrets, or notification bodies.

## Test coverage

- Distinct created/updated/deleted notification IDs enqueue independently.
- Exact redelivery of one notification ID enqueues once.
- Same-type updates without ID/version both enqueue.
- Same message/etag in different team/channel/subscription contexts cannot collide.
- Duplicate audit output contains no clientState.
