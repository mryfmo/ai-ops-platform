## 整理の原則 — 80 件は 80 個の作業ではない

「残り 80 所見」と数えるのが非効率の元。**根本原因で束ねる**と 6 群になり、群ごとに経済性がまったく違う。

| C | 承認フローが未完成 | 3〜4 | **裁定 D-01** | 直列 |
| D | 検証ゲートの穴 | 約 10 | なし | 並列可 |
| E | 独立した小欠陥（セキュリティ・堅牢性） | 約 19 | なし | **広く並列可** |

**効率を決めるのは重大度ではなく裁定のリードタイム。** 重大度順に並べると群 B が先頭に来るが、これは人間の判断待ちで数日かかり得る。その間、裁定不要の群 D/E（約 29 件）が寝る。原則は **「裁定は即座に出して非同期化し、待つ間に裁定不要の作業を焼き切る」**。

### 新規所見（2026-08-07、A025 の実測中に発見。**監査 81 件に含まれない**）

**ADV-VER-014 [High] PRD に定義された受入条件が spec-ids / カタログの双方に存在せず、完全に不可視**

- 実証: `docs/spec/prjops/03_PRD.md:104,105,109` は `AC-011〜015共通-1`、`AC-011〜015共通-2`、
  `AC-016-1` を定義しているが、`packages/traceability/spec-ids/prjops.json` の AC 39 件にも
  `docs/spec/spec-id-catalog.md` にも存在しない（カタログは AC-010-3 から AC-017-1 へ飛ぶ）。
- 原因は 2 系統ある。`AC-016-1` は**単なる登録漏れ**（ID 書式はツールの文法に適合する）。
  `AC-011〜015共通-*` は**文法が表現できない**（`AC-\d{3}(?:-\d+|[a-z])?` に範囲記法が入らない）。
- 構造的な穴: カタログガードは index ↔ カタログを突合するだけで、**正本（PRD）↔ index を突合しない**。
  したがって PRD にしか無い AC は、どちらのガードにも掛からず永久に不可視になる。ADV-VER-006 の
  「disposition が欠落 ID と連動しない」より 1 段深い層の問題。
- 実害: `AC-011〜015共通-1` は「各プロファイルのレポートに非表示指定の情報が一切含まれない」という
  **権限フィルタの受入条件**であり、`reportPermissionFilter.ts:5` から参照されているのに
  トレーサビリティ上は存在しない。CLAUDE.md 設計原則 6 の中核が機械検証の外にある。
- **裁定が必要（D-10）**: 範囲記法 AC をどう表現するか。(a) PRD を `AC-011-1`〜`AC-015-1` に展開する、
  (b) ツールの文法に範囲記法を追加する、(c) 代表 ID に正規化する。**推測で決めてはならない。**

### レビュー往復の実績（2026-08-07）

Codex レビューは #128 で 5 巡・計 15 スレッド、#129 で 6 巡。うち **2 件は「私の修正自体が
機能していない」という指摘**で、いずれも正しかった。

1. reaper の相関キーを `agent/<task_id>` ブランチにしたが、dispatch の `ref` は `main` で
   作業ブランチは run に紐づかないため常に空を返し、**全 stale 行が誤って回収される**状態だった。
2. dispatch 不確定時に failed で終端させる判断は、**reaper を入れる前なら妥当だが入れた後は誤り**。
   running のまま残せば二重起動も防げて誤終端も避けられる。

教訓: 自分の修正が生んだ新しい失敗様式は、自分では見えにくい。**独立したレビュアーに
「この修正は本当に効いているか」を問わせる往復を、修正のたびに回すこと。**

## 並列割当の必須条件（agmsg 規約）

並列は次の 4 条件を**全て**満たすときのみ有効。

1. 各ワーカーが専用 git worktree を持ち、それを agmsg の `project` として登録している
2. 共有デフォルト store を使う（同一リポジトリ並列で `AGMSG_STORAGE_PATH` を分けない）
3. 並列時は**全員**が `-aNNN` 接尾辞を持つ（先発ワーカーも例外なし）
4. `allowed_files` が in-flight タスク間で pairwise disjoint

**排他性の機械検証（2026-08-05 実施）**: A022〜A027 の `allowed_files` は pairwise disjoint = OK。当初 A023/A026/A027 が `packages/server/tests/**` をワイルドカードで確保して衝突していたため、テストファイルを実名に確定して解消した。**割当変更や新規タスク追加のたびにこの検証を再実行すること。ワイルドカードを 1 つ入れた瞬間に条件 4 が崩れる。**

なお ai-ops-platform の agmsg 識別子は 2026-08-05 に 10 → 2 へ整理済み（規約準拠）。
