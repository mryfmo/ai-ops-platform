# P005-T06 Learning Triage

## Reusable learning

- A Teams manifest test should require the complete exact RSC array, not merely the presence of desired permissions; presence-only checks allow stale or tenant-broad permissions to remain.
- Microsoft Teams' RSC permission reference and Microsoft Graph's channel post/reply method permission tables conflict for app-only ordinary sends as of 2026-07-11. Documentation evidence alone cannot establish runtime conformance.
- Permission-use documentation must cover every accepted caller: `sendAdaptiveCard` root posts and `replyToMessage` replies both rely on the send permission.
- Pinning a manifest's `$schema` URL/version is not schema validation. A placeholder manifest must be replaced, packaged, and checked with the real Teams schema before deployment readiness can be claimed.
- Architecture docs must distinguish a desired installation path from implemented automation; this repository currently requires manual Teams app installation/consent.

## Disposition

- Retained as task learning only; no rule was promoted and no registry state changed.
- Promote only after sandbox evidence or Microsoft support resolves the ordinary app-only send conflict, Plan008 validates a packaged manifest, or another manifest repeats the exact-permission regression.
