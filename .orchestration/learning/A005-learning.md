# A005 Learning

## Candidate reusable learning

A development default that intentionally violates a production acceptance criterion should be recorded as a separate, visibly tagged layer rather than weakening the production criterion. The record should enumerate the placeholder values, state what remains uncreated or unapproved, preserve the production BLOCKED status, and define the exact real-value replacement gate.

Crit CLI also treats `crit comment --help` as a comment body rather than help output. Use top-level `crit --help` or the skill reference for subcommand syntax. If invoked accidentally, clear the transient record before creating review evidence.

## Triage

- Reusable: yes, for future dev-phase overrides and Crit CLI automation.
- Validated: yes, by the A005 decision record, unchanged production status, resolved Crit review, and green local/hosted CI.
- Promotion: not performed; A005 records candidates only.
- Worklog learn update: not performed because the task forbids worklog edits.
