# P005-T08 Learning Triage

## Reusable learning

- Retry policy must classify non-idempotent POST separately from safe/idempotent operations; a generic 5xx retry can duplicate mail and Teams messages.
- Provider retry headers need grammar and arithmetic validation before sleeping. Valid server delay is authoritative, while locally generated fallback jitter remains locally capped.
- Correlation hooks are an observability boundary: validate identifiers/dates, expose a fixed metadata shape, and isolate hook failures from delivery semantics.
- Injected request-ID providers are test seams, not trust boundaries; validate their output and preserve per-attempt uniqueness even when they repeat values.
- Correlation uniqueness does not require retaining every past UUID: a fixed-width per-client sequence can provide constant-space uniqueness while preserving UUID syntax and provider entropy.
- Server-directed delays can exceed the native timer range. Chunk only the native timer implementation; keep injected sleep at one exact total call so deterministic tests do not simulate multi-day time in platform-sized pieces.

## Disposition

- Retained as task-local candidate learning. No rule/skill promotion and no repository learn-index update were performed.
- Promote only if another external client repeats the same observer rejection, retained-ID history, or native long-timer failure mode.
