# P005-T10 Learning Triage

Candidate reusable rules:

- When a downstream audit layer stringifies exceptions, replace the exception at the nearest allowed caller boundary with a new fixed error without `cause`; never pass the original object.
- If a legacy client exposes status only in a fixed message, parse an anchored exact known shape. Any suffix or arbitrary text must produce `unknown`, not a partially parsed status.
- Reuse the shared canonical stakeholder validator for persisted ST IDs; separately accept only numeric U IDs and versioned UUIDs. Prefix-only validation admits named PII.
- Distinguish idempotent duplicate skip from retry evidence. In this server path, `pending` delivery state is the real retry trigger; the lower-level explicit retry flag is not exposed.

Validated by focused mail/card, named-ID rejection, pending retry, duplicate skip, and logger tests. Kept as task-local triage only; no learn index or rule promotion was performed because the task permits only the five artifacts.
