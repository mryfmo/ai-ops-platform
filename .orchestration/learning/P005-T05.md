# P005-T05 Learning Triage

## Reusable learning

- Restart recovery must be opt-in per scheduled task; initializing only those tasks as immediately due preserves the existing interval and non-overlap mechanism.
- Invalid subscription expiry is a recovery signal, not a reason to skip work.
- Graph recovery audits should retain only status/state identifiers; exception text can contain service response details or secrets.
- Replacement must persist Graph's returned expiry and update only subscription identity/expiry/mode so resource, team, channel, and delta continuity survive.
- 404 means the old subscription cannot be renewed and needs replacement; exhausted 429/5xx remains recoverable polling state and must not trigger duplicate non-idempotent creates.
- Scheduler cadence must use a monotonic clock while task policy receives wall time; backward wall-clock correction must not create a hot loop.
- A PostgreSQL session advisory lock can serialize recovery owners across processes, but Graph create + backfill + conditional DB publish is not one atomic transaction. A newly created subscription needs bounded cleanup on every pre-publish failure and reconciliation when cleanup fails.
- Replacement must rebuild the canonical resource from validated ledger team/channel IDs rather than trusting a stale stored resource string.
- Background/best-effort handlers need structured bounded error fields; raw exception messages can contain Graph response bodies.
- Advisory lock acquisition alone is insufficient: after waiting, re-read the ledger under the lock and reject a stale old ID/mode before any non-idempotent Graph create.
- Startup serialization and periodic cadence are separate state: release each completed startup task's cadence without waiting for a later startup task to finish.
- Advisory unlock is a correctness check. A false/failed unlock must destroy the checked-out connection via `release(error)` rather than return uncertain session state to the pool.
- Recovery ledger identifiers must be exact canonical stored values; silently trimming whitespace can target a different Graph resource.
- An external cleanup result and its audit-persistence result are separate outcomes. A successful DELETE remains successful even if recording `cleanup_complete` fails; only the DELETE failure may imply an orphan risk.
- A scheduler timer registry must represent every not-yet-fired handle: add on schedule, remove when the callback starts, and clear the entire active set during stop.

## Disposition

- Retained as task learning only; no skill/rule promotion or learn_index update was performed.
- Promote only if another Graph subscription resource repeats the same atomic replacement and status-classification pattern.
