# P005-T09 Learning Triage

## Reusable learning

- MSAL client-credential callers should invoke `acquireTokenByClientCredential` on every sequential request and let the application cache decide cache/refresh behavior; a wrapper TTL cache duplicates SDK policy and can serve stale tokens.
- A single in-flight Promise is sufficient to prevent concurrent duplicate acquisition, provided it is cleared in `finally` so rejection cannot poison later calls.
- Authentication boundaries should replace SDK errors and malformed results with a fixed classification error; forwarding status, response body, token, or SDK message risks credential disclosure.
- A token that is nonblank only after trimming still needs an explicit contract: this provider fails closed rather than silently normalizing or forwarding surrounding whitespace.
- A green CI does not clear dependency risk: the orchestrator's production audit still reported 1 low and 3 moderate advisories on existing non-MSAL paths.

## Disposition

- Retained as task-local validated learning. No skill/rule promotion or `.agents` update was performed under the task boundary.
- Apply to future app-only identity wrappers only when the SDK already owns caching and refresh.
