# A038 Learning Candidate

## Candidate

For a manual status override, validate an unredacted actor at every trust boundary and sanitize an operator-supplied reason before it reaches the audit writer. Guard the update by the source status and append the audit record through the same PostgreSQL transaction client. Preserve retry counters when they are cumulative operational history; document that this gives one controlled retry and an immediate return to the terminal state on another failure.

When a historical test fixture resembles a credential, prefer making HEAD obviously fake. If the historical commit must still scan, use a Gitleaks allowlist that conjunctively matches the specific rule, exact path, and exact fixture line; a path-wide allowlist silently hides future leaks.

## Promotion decision

Do not promote to the shared learn index. The reusable constraints are now executable in focused tests, the runbook, and `.gitleaks.toml`; another prose rule would duplicate those controls.
