# P005-T04 Learning Triage

## Reusable learning

- Teams `chatMessage` subscriptions must be governed by the resource-specific Graph v1.0 contract rather than generic stale Teams lifetime text.
- Validate subscription resource, callback URLs, change types, client state, and expiration before credential acquisition or network work.
- Persist Graph's returned expiration; the requested expiration is not authoritative after service-side normalization.
- Workspace consumers may typecheck against a changed package's `dist`; rebuild the producer before trusting downstream focused typechecks.
- JavaScript `Date.parse` accepts non-RFC3339 forms; Graph DateTimeOffset boundaries need explicit syntax, calendar, future-time, and resource-lifetime checks with an injected clock.
- URL path validation must compare the decoded-and-rebuilt canonical form, otherwise encoded whitespace, separators, and double encoding can bypass segment checks.
- Revalidate service-returned ledger fields at the persistence boundary so injected clients and future implementations cannot bypass transport validation.
- Trimming only detects edge whitespace; opaque path IDs also need decoded internal Unicode whitespace/control rejection, with positive punctuation cases to prevent an overbroad allowlist.

## Disposition

- Retained as task learning only; no rule was promoted and no registry state changed.
- Promote only if another Graph resource lifecycle repeats the same resource-specific contract or returned-expiry failure mode.
